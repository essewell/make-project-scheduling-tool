Mobile sheet spring physics model

The sheet uses height + translateY in combination. No JS spring library needed.

// dragRef tracks touch state across events (useRef, not useState — avoids re-renders)
const dragRef = useRef<{
  startY:   number;  // initial touch clientY
  lastY:    number;  // previous frame clientY
  lastTime: number;  // previous frame timestamp (ms)
  velocity: number;  // px/ms — positive = downward
}>({ startY: 0, lastY: 0, lastTime: 0, velocity: 0 });

// velocity = (currentY - lastY) / deltaTime
// At touchEnd:
if (velocity > 0.5 || delta > 80)  onClose();      // fast flick OR big drag → dismiss
else if (Math.abs(delta) < 12)        togglePeekFull(); // tap → toggle
// else: dragY=0 → spring snaps back to current sheetState

// Snap targets — CSS height values:
// peek: 40vh  (title + handle + group tag visible)
// full: 85vh  (all fields visible)
// During drag: sheet-dragging class suppresses transition; transform: translateY(dragY)px live
// On dismiss:  sheet-dismissing class → height: 0 fast ease-in 0.22s

Onboarding State MachineNew v4

Not a component — a state machine driven by onboardingPhase useState. Persisted to localStorage as part of saveState().

'fresh' → Initial state. Empty state CTA is the primary affordance. No other onboarding UI shown. Trigger: no tasks, no stored data.
'first_added' → First task created. Gantt area gets .onboarding-pulse class → schedule-gantt-pulse animation (2 cycles × 1.4s). Remove class after 3200ms. Trigger: tasks.length ≥ 1 AND prev phase was 'fresh'.
'baseline_tip' → 3+ tasks exist. .baseline-onboarding-tip tooltip renders near Baseline button. pointer-events: none (non-blocking). Dismissed when user clicks Baseline button naturally. Trigger: tasks.length ≥ 3 AND prev phase was 'first_added'. Delay: 900ms setTimeout.
'complete' → Onboarding retired. No UI shown. Stays complete permanently. Trigger: baselines.length > 0 (user locked a baseline). Works from any prior phase.

Derived value (not useState): showBaselineTip = onboardingPhase === 'baseline_tip' && baselines.length === 0. Example-data users: start at 'fresh', immediately advance to 'first_added' (19 tasks), then to 'baseline_tip' after 900ms — this is intentional, they still benefit from the baseline tip.

Interaction Flows

1 · First-run onboarding (fresh → complete)

1
No stored data → SetupWizard shown. User enters project name + chooses blank or example data. Wizard dismisses, onboardingPhase = 'fresh'.
2
User adds first task (blank start) or loads example data → onboardingPhase advances to 'first_added'. Gantt area pulses with schedule-gantt-pulse (2 cycles, 3200ms total).
3
When tasks ≥ 3 → after 900ms delay, onboardingPhase = 'baseline_tip'. Dark tooltip appears above Baseline button: "Track schedule variance — Lock the current plan as a baseline snapshot…"
4
User clicks Baseline → Lock → onboardingPhase = 'complete'. Baseline tip disappears. UndoToast: "Locked baseline Baseline v1". Onboarding retired permanently.

2 · Print preview → print execution

1
User clicks PDF in topbar → setShowPrintPreview(true). PrintPreviewModal opens (schedule-fade-in overlay + schedule-slide-in chrome).
2

Developer Notes & Constraints

What not to change

  • Custom Gantt rendering — no third-party chart library. Bars are absolutely positioned divs, not SVG or canvas. The entire horizontal layout is computed from dayPx × day offset.
  • Token architecture — every new component must use existing CSS vars. No new hardcoded hex values (print page exceptions are documented above).
  • Dark mode — all new components require overrides inside @media (prefers-color-scheme: dark).
  • Dependency arrow SVG — absolute-positioned <svg> overlay on the Gantt body, z-index 5.
  • localStorage key — schedule-tool-v1. Add new fields to the existing object; never change the key or it orphans saved data.
  • Keyframe namespace — all new @keyframes must be prefixed schedule- to prevent collision with host-page or third-party CSS.
  • Scroll sync — task list and Gantt scroll together via syncingScroll ref flag (prevents feedback loops). Preserve this pattern.
  • Font features — font-feature-settings: "tnum" on all mono elements for tabular number alignment.
  • Row height coupling — ROW_HEIGHT = 36 must be consistent across TaskList, Gantt body, GanttGrid, and DependencyArrows. If changed, update all four simultaneously.

Working days calculation

// v4: WORKDAY_RATIO (5/7) hardcoded in helpers. Replace with:
function workdayRatio(workweek: WorkweekConfig): number {
  return Object.values(workweek).filter(Boolean).length / 7;
}
function workdays(task: Task, ww: WorkweekConfig): number {
  return Math.round(durationDays(task) * workdayRatio(ww));
}

Clarifications for Claude Code

Ambiguities and gaps in the v4 prototype that need a decision before implementation.

⚠ C1 — depType and lag not persisted to Task

Issue: LinkBuilderModal.onSave receives (deps, depType, lag) but handleSaveLinkBuilder in App only calls updateTask(selectedId, { deps: selectedDeps }). The depType and lag values are discarded.

Recommendation: Add to Task interface: depType?: DepType (default 'FS') and lag?: number (default 0). Save all three from the modal. The prototype stores deps as a flat string[] which implies single dep type per task — either extend to per-dep storage (deps: Array<{ id: string; type: DepType; lag: number }>) or keep per-task overrides for simplicity. Confirm with stakeholder before implementing.

⚠ C2 — ghostStyle not persisted to localStorage

Issue: ghostStyle is in App state but omitted from saveState(). It resets to 'stripe' on every page reload.

Recommendation: Add ghostStyle to PersistedState and saveState() call. It is a preference users will expect to persist. Low risk — no migration needed (absent key defaults to 'stripe').

⚠ C3 — Actual date validation is advisory only

Issue: The actual-date cross-field validation (finish before start) shows an inline error but does NOT block saving. The prototype renders the error and allows the invalid state to persist in localStorage.

Recommendation: Decide whether validation should be enforced (block save, revert field) or advisory (current behaviour). If enforced, disable the finish date input until a valid start is entered.

⚠ C4 — WBS numbers recalculate on every render

Issue: WBS numbers are computed inline in TaskList on every render using a two-pass row scan. At 500+ tasks this is negligible but should be memoised in the Vite implementation (useMemo over visibleRows).

⚠ C5 — Example data bypass of onboarding

Issue: Users who click "Load example data" start with 19 tasks. The onboarding effect immediately fires first_added (gantt pulse) and then after 900ms fires baseline_tip. The pulse animation fires for example-data users — this may feel premature since they didn't create the tasks.

Recommendation: Either (a) skip onboarding entirely for example-data users by setting onboardingPhase = 'complete' in startProject(name, withExample=true), or (b) keep current behaviour (tip still useful). Confirm intent.

⚠ C6 — kb-focused + selected combined state rendering

Task rows can have both .kb-focused and .selected simultaneously. Current spec: selected provides --color-selected-bg fill; kb-focused adds outline: 2px solid var(--accent). This is visually correct but note that outline-offset: -2px means the ring draws inside the row border. Verify this renders acceptably across browsers — may need a :focus-visible polyfill for users navigating by pointer.
